# History — chat knowledge

- Owns everything Derp knows about a chat: `chats`, `users`, `forum_topics`, `messages` + `message_media`, `chat_members` + `member_events`, `reactions` + `reaction_counts`, `polls` + `poll_votes`, `stickers`, `digests`.
- Storage shape: normalized core columns for what queries filter on, a typed `payload` JSONB per message kind (dice, location, contact, checklist, poll, service event…), and `raw` JSON only for kinds without a typed shape. Contacts and precise locations are stored in full and follow retention.
- `capture.py` upserts by Telegram IDs, so redelivery and edits are idempotent; edits replace text/payload in place, and an edit that swaps a file drops that file's transcript/description. Derp's rich messages are stored with the Markdown that was sent (Telegram returns only blocks). `message_id == 0` (ephemeral) and guest-mode messages are never stored. Only agent outputs are recorded as Derp's messages (`capture='derp'`), not UI/system copy.
- `middleware.py` runs before handlers: invocations are always stored; other group messages only while the chat's ambient context is on. The message an invocation replies to is part of the invocation and is stored too if it wasn't (privacy mode, ambient off). It hands `trigger` and `chat_row` to handlers.
- `members.py`: every non-bot sender of a group message gets a `chat_members` row (last few display names, message count of stored messages). Join/leave service messages and `chat_member` updates (only delivered while Derp is an admin) append `member_events`. `chats.profile` is a JSON snapshot of `getChat` + admins + member count, refreshed when Derp joins and hourly for active chats whose snapshot is older than a day.
- `reactions.py`: reaction updates reach Derp only as an admin; an actor's new list replaces their old one, and reactions on messages Derp didn't store are dropped so they share the message's policy and retention. Keys: the emoji itself, `custom:<id>`, or `paid`.
- `polls.py`: poll rows come from captured poll messages (`origin` derp_poll / derp_quiz / user). Telegram sends live state only for Derp's own and stopped polls, and votes only for Derp's non-anonymous polls; updates for polls never captured are ignored. Votes keep persistent option ids because options can be added after voting starts.
- `render.py` turns rows into compact transcript lines (`[HH:MM] #id Name ↩#reply: text [media: note] {🔥3}`) in the chat's time zone; shared by the context window and history tools. Contacts render without phone numbers. Untrusted text goes through `neutralize` (can't close Derp's data tags; continuation lines are marked so they can't pose as new messages) and names/titles through `one_line`.
- `thread_id` is set only for forum-topic messages, so "this topic" queries never mix topics.
- Full-text search uses the `simple` configuration over `text` + `extra_text` (transcripts, media descriptions) via the generated `tsv` column; always pass `'simple'` to query functions (the server default config drops stop words). Trigram index on `text` covers fuzzy matches.
- Rows are always scoped by `chat_id`; query helpers take the chat from the run context, never from tool arguments.
- `queries.py` is the read side: `search` (ranked FTS `simple` + trigram top-up), `around` / `id_range`, `resolve_members` (current and past names, @username) and `ChatQuery` — a typed request (presets, filters, group_by, order, limit ≤ 200) compiled to SQL here. Model input never becomes SQL text, and the chat id always comes from the caller.
- `transcription.py`: every stored voice message / video note is transcribed inline during capture (so voice invocations are answered from the transcript): creator-funded STT (`kind='stt'`, fallback model on any error), video notes via ffmpeg → OGG/Opus, recordings over `media.voice_max_seconds` skipped. The transcript lands in `message_media.transcript` and `messages.extra_text` (searchable); nothing is posted.
- `stickers` is a global index of regular stickers seen in any chat Derp is in, stored or not (public assets: emoji, set, use count, `curated`; no sender), the pool `send_sticker` draws from; custom emoji are skipped.
- `digests.py`: `digests` rows summarize one chat day (chat time zone) for the whole chat (`thread_id` 0) or one topic. They are built lazily by the agent and reused while current: not stale, and no message newer than `last_message_id` in that day. Any edit or deletion inside a digest's id range marks it stale.

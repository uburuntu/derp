# History — chat knowledge

- Owns everything Derp knows about a chat: `chats`, `users`, `forum_topics`, `messages` + `message_media`, `chat_members` + `member_events`, `reactions` + `reaction_counts`, `polls` + `poll_votes`, `game_scores`, `daily_titles`, `stickers`, `digests`.
- Rows are always scoped by `chat_id`; query helpers take the chat from the run context, never from tool arguments. `thread_id` is set only for forum-topic messages, so "this topic" queries never mix topics.
- Storage shape: normalized core columns for what queries filter on, a typed `payload` JSONB per message kind (dice, location, contact, checklist, poll, service event…), and `raw` JSON only for kinds without a typed shape. Contacts and precise locations are stored in full and follow retention.
- Bot-specific ids: `message_media.bot_id` and `stickers.bot_id` record which bot received each `file_id` (a test or successor bot can't use another bot's); `file_unique_id` is the cross-bot key. `stickers` is a per-bot global index of regular stickers seen in any chat Derp is in, stored or not (public assets: emoji, set, use count, `curated`; no sender), the pool `send_sticker` draws from; custom emoji are skipped, and the emoji is stored plain (`telegram.text.plain_emoji`) so queries compare it as is.
- `capture.py` upserts by Telegram IDs, so redelivery and edits are idempotent; edits replace text/payload in place (never on a forgotten, tombstoned row: it stays scrubbed, media included), and an edit that swaps a file drops that file's transcript/description. Derp's rich messages are stored with the Markdown that was sent (Telegram returns only blocks). `message_id == 0` (ephemeral) and guest-mode messages are never stored. Only agent outputs are recorded as Derp's messages (`capture='derp'`), not UI/system copy. `message_values` is the one Telegram → row mapping; `unstored_view` renders a message that isn't stored (an ephemeral command, a reply Derp never kept) through it, like any line.
- `middleware.py` runs before handlers: invocations are always stored; other group messages only while the chat's ambient context is on, except that an edit always updates a message already stored; bot commands never (controls, not conversation — edits included); nothing from an owner-blocked chat or person is stored or transcribed. The message an invocation replies to is part of the invocation and is stored too if it wasn't (privacy mode, ambient off). It hands `trigger` and `chat_row` to handlers.
- `members.py`: every non-bot sender of a group message gets a `chat_members` row (last few display names, message count of stored messages; `offered_on` is money's once-a-day out-of-Derpcoins offer, `money/free.py`). Join/leave service messages and `chat_member` updates (only delivered while Derp is an admin) append `member_events`. `chats.profile` is a JSON snapshot of `getChat` + admins + member count, refreshed when Derp joins and hourly for active chats whose snapshot is older than a day.
- `reactions.py`: reaction updates reach Derp only as an admin; an actor's new list replaces their old one, and reactions on messages Derp didn't store are dropped so they share the message's policy and retention. Keys: the emoji itself, `custom:<id>`, or `paid`.
- `polls.py`: poll rows come from captured poll messages (`origin` derp_poll / derp_quiz / user). Telegram sends live state only for Derp's own and stopped polls, and votes only for Derp's non-anonymous polls; updates for polls never captured are ignored. Votes keep persistent option ids because options can be added after voting starts. A member's first answer to a Derp quiz scores `game_scores` (+1/−1 per chat-local day, floored at 0; the `quiz_leaderboard` chat query reads it). `titles.py`: titles of the day — one winner per (chat, normalized title, chat-local day), drawn at random among members still in the chat and seen within `ACTIVE_DAYS`; a second ask that day returns the stored winner (insert-or-keep, so concurrent asks agree); `leaderboard` counts wins (the `title_leaderboard` chat query). Scores and titles don't follow retention; `forget_member` drops a person's.
- `render.py` turns rows into compact transcript lines (`[HH:MM] #id Name @username ↩#reply: text [media: note] {🔥3}`; senders by `User.label`, so the model can tag people) in the chat's time zone; shared by the context window and history tools. Output is deterministic (reaction ties by key); the context window renders without reaction totals so old lines stay byte-stable for the prompt cache. Contacts render without phone numbers. A reply to a message in another chat or topic (`payload.external_reply`) shows its origin and kind (`↩ (from News: photo)`), followed by the quoted part when there is one; origins are named as forwards are (`_origin_source`) and kinds as media are (`kind_label`). A message never stored (id 0) has no `#id`. Untrusted text goes through `neutralize` (can't close Derp's data tags; continuation lines are marked so they can't pose as new messages) and names/titles through `one_line`. `links.py` is the way back: `message_links` resolves an answer's `#id` references to this chat's stored messages (`Chat.message_link`: by username in public chats, `t.me/c/…` in private supergroups, none in basic groups and private chats), code and unknown numbers untouched, and hands the sender the rewrite (answers and edits alike); history keeps the text as written. Notes and jobs are "note 42" / "job 12", never `#`.
- `queries.py` is the read side: `search` (ranked FTS + trigram top-up), `around` / `id_range`, `resolve_members` (current and past names, @username) and `ChatQuery` — a typed request (presets, filters, group_by, order, limit ≤ 200) compiled to SQL here. Model input never becomes SQL text, and the chat id always comes from the caller. Full-text search uses the `simple` configuration over `text` + `extra_text` (transcripts, media descriptions) via the generated `tsv` column; always pass `'simple'` (the server default config drops stop words). A trigram index on `text` covers fuzzy matches. Days are the chat's: `Scope.tz` sets `group_by='day'` boundaries and reads offset-less `since`/`until` as chat-local.
- `transcription.py`: every stored voice message / video note is transcribed inline during capture (so voice invocations are answered from the transcript): creator-funded STT (`kind='stt'`, fallback model on any error), video notes via ffmpeg → OGG/Opus, recordings over `media.voice_max_seconds` skipped. Ambient voice (not part of an invocation) stops once the UTC day's creator-paid STT reaches `ambient_stt_daily_usd` (one owner ping per day); the voice an invocation replies to is transcribed on demand whenever it has no transcript. Audio files are transcribed only as part of an invocation (sent with it or replied to; non-OGG via ffmpeg), never ambient. A recording that won't get one stores an empty transcript (like an empty image description) with why in `transcript_model` (`TOO_LONG`, `UNHEARD`), which `render.py` shows ("[voice 12:04 — too long to transcribe]"): stored, so lines stay stable; an `UNHEARD` one is retried when an invocation replies to it. Which messages are transcribed is decided only in `Transcriber.transcribe`; a request that waited on one in flight reports its transcript. Updates run concurrently, so `Transcriber` tracks transcriptions in flight per (chat, message): a second request for the same message waits for the first, and `Runtime` calls `settle` (bounded by `SETTLE_SECONDS`) so a run doesn't read the chat while an earlier voice note of its topic is still being transcribed. The transcript lands in `message_media.transcript` and `messages.extra_text` (searchable); nothing is posted.
- `digests.py`: `digests` rows summarize one chat day (chat time zone) for the whole chat (`thread_id` 0) or one topic. They are built lazily by the agent and reused while current: not stale, and no message newer than `last_message_id` in that day. An edit inside a digest's id range (or Derp deleting its own message there) marks it stale: never shown, rebuilt on the next ask. Forgetting deletes covering digests instead, so nothing summarizing what someone took back stays stored. `retention.py`: raw history (messages + media, reactions, polls/votes, member events) lives for `chats.retention_days`, else the private/group default (`kept_days`, and `retention_days` for the same rule in SQL); digests for `retention.digest_days`. `forget_message` / `forget_member` tombstone and scrub rows and delete every digest whose id range covers them (rebuilt on demand without them); `purge_ambient` deletes ambient rows and the chat's digests.

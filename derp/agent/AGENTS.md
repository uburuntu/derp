# Agent

- `models.py`: `agent_runs` (one row per invocation: trigger, funding, served model, usage, cost, charge, Pydantic AI history) and `run_outputs` (every delivered message/poll/sticker/image/reaction, so `/info` resolves any output to its run). `runs.py` owns the run lifecycle: `finish_run` is the single place that ledgers a run's provider responses and stores its history; stored history replaces inline binary with markers, follows the chat's retention (`expire_run_messages`) and is dropped by privacy actions (`scrub_runs`); a run without history is replayed as its visible text.
- `invocation.py` decides what invokes Derp: every private message; in groups @mention/text mention, replies to Derp, or Derp's name (en/ru inflections and diminutives, not compounds). Bots never trigger (loop guard), anonymous admins do. Commands are a separate trigger kind handled by routers; `handler.py` is the last router: any invocation no command claimed goes to the runtime.
- `lanes.py`: runs queue per (chat, forum topic) so each sees the previous answer; while someone waits, their newer invoking message supersedes the older one (it is already in the newer run's window); a global semaphore (`settings.run_concurrency`) bounds runs in flight. `Runtime.answer` also skips triggers that already have a run (redelivered updates).
- `context.py` builds the recent window before the current message: members' messages become `<chat_history>` transcript blocks (untrusted data), Derp's replies are replayed from their completed runs (tool calls + clipped results, no thinking, no original prompt; history that can't be loaded falls back to the visible text). Runs are kept whole; the window never opens mid-run; only ids below the trigger are read, scoped to the trigger's forum topic. Budgets are estimated tokens (UTF-8 bytes / 4). For prompt caching the runtime remembers each topic's window start per funding tier (`Runtime.window_starts`, in memory; tiers differ in budget and model) and keeps it while the window fits in `STICKY_SLACK` × the budget (rows too), so consecutive runs extend the same prefix; past that it starts afresh. Old lines must not change between runs: the transcript leaves out reaction totals (history tools show them), and replayed runs clip long tool results and long string arguments of tool calls (code, image prompts) deterministically.
- `runtime.py` runs one invocation: the money `Funder` reserves from the first payer that can cover a turn (no payer → the out-of-Derpcoins offer, in groups once per person per UTC day and a 🙈 reaction after that; no run), which fixes the tier and model role; the run row is opened, the window is built, the agent runs under caps (tool calls, per-request output tokens, wall time, the money hold), the answer goes out via the sender, and `finish_run` closes the run with every provider response (failed runs included, via `capture_run_messages`). Failures — setup included — get a short localized apology unless something was already sent (a 429 on free models says they're busy; it and the money-cap notice say "not charged" only when nothing was charged, else that the work so far was), and any failure after the reservation releases the hold. A model that can't see images is told so in the situation block rather than guessing. Before each tool call the run's spend so far is checked against its hold; reaching it stops the run like a user stop (the backstop: `guard.py` wraps up first). After delivery the run settles: charged if anything reached Telegram (parts of a half-sent answer included), released otherwise. A charge to a chat wallet that leaves it unable to pay a turn posts the silent empty-wallet line once (`Funder.ran_dry`; approved actions too).
- `guard.py` (a per-run capability plus a model wrapper) makes caps end in an answer: at the soft caps (the tool calls allowed, requests, three quarters of the wall time, or a hold the next request would reach) requests go out with `tool_choice='none'` and a request-only note, schemas kept for the cache, and a tool called anyway is refused; a request web search was left out of (`deps.search_withheld`) gets an "out of budget" note; Pydantic AI's usage limits sit `BACKSTOP` above. Once per run, an unanswered reply (empty, thinking only, or cut off by the token limit before text or a complete tool call; the retry then gets double the output tokens) or a request the provider refused to start (429, 408, 5xx, connection) is retried on `RolePin.rotated()`, which serves the rest of the run. A retry continues the run, so tools that ran are not repeated; errors after streaming began are not retried. `prefix.py` measures the prompt prefix (persona + the tier's up-front tool schemas + a fixed allowance) that turn prices add to the window: `Funder` minimums and `price_unreported`.
- `persona.py`: the persona is the only system instruction and never changes; the per-run `<situation>` block (place, topic, time, asker, rules, notes, chat profile framed as data) opens the final request, after the window, so tools + persona + window stay a cacheable prefix. Members can't forge `<situation>` (`neutralize`). `deps.py`: `RunDeps` (chat, asker, reply target, `funds` with the funding tier and hold, delivered outputs).
- `tools/` holds the tool families, their tiers and capabilities (see `tools/AGENTS.md`). `media.py`: images a run inspects — the current message's (album included) and the replied-to message's, or any stored message via the `inspect_media` tool, which also sees videos, GIFs and video notes through one still frame (`derp.tools.effects.still`). Vision pins (`RolePin.vision`) get the pixels; every inspected image without a note gets a one-line description (a separate small call on the run's own pin, ledgered as `kind='media'` against the run, failed and empty responses included) stored on `message_media.description` and folded into `messages.extra_text`. A run's notes are made concurrently under a timeout; a paid note that came back empty stores `''`, so the image is never described (or paid for) again. Ambient media is never downloaded.
- `digests.py` builds day digests (see `history/digests.py`) on a cheap pin — sponsored, or free on free runs — ledgered as `kind='digest'` against the asking run. Paid runs may build a week per tool call, others one day; a day too long for one call is summarized in parts and merged. The latest digest ending before the context window (if from the last few days) joins the situation block as data.
- `images.py` generates and edits images on the image pin via the Images API (paid funding only); the provider call is ledgered against the run only after Telegram accepted the photo (otherwise absorbed as `creator`). `approvals.py`: actions above `approval_credits` or `approval_balance_fraction` of the payer's balance post a Run / Cancel prompt (price only, never a balance) instead of running; `approvals` rows keep the action's arguments for `approval_minutes` and are deleted after a day. Only the requester decides, once. Run funds the action afresh as its own run (`Runtime.run_approved`, trigger `callback`), queued in the chat topic's lane so the run that posted the button has settled its hold, from the first payer whose paid Derpcoins cover the price; Cancel and expiry cost nothing.
- `inline.py`: inline mode (one placeholder result with a keyboard so Telegram reports its `inline_message_id`; the answer is edited in on `chosen_inline_result`) and guest mode (one `answerGuestQuery` reply). Both use `Runtime.answer_detached`: the asker's personal funding, no chat history or function tools (web only), no stored messages or run history; charged only after the answer is in.
- `progress.py`: private chats stream the answer into a `sendRichMessageDraft` (throttled, `<tg-thinking>` step label, stop button); groups get a chat action that follows the stage (`upload_photo` while drawing, `typing` otherwise) — never a status reaction, which would notify the asker. A refused draft falls back to the chat action; progress never fails the run. Every run streams (an event handler is always passed), so a response cut off by stop or timeout is kept as `state='interrupted'`; `runs.price_unreported` prices every paid response without a cost (cut off or not; runs, detached answers, digests, media notes): OpenRouter's cost by generation id, else its tokens at the pin's price snapshot; free-model responses stay 0. Stop (`stopped_message_generation`) cancels via the run's `CancellationToken`; the partial answer is posted and the run ends `cancelled`.
- Tests: e2e journeys swap the chat model through `Services.model_factory` (`tests/e2e/model.py` `ScriptedModel`); nothing in the offline suite calls a real model.

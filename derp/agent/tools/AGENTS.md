# Agent tools

- One module per tool family, registered in `__init__.py` `FAMILIES`. A `Family` (`../toolsets.py`) names the funding tiers that may use it (paid, sponsored, free) and which tools are deferred. Only free-model runs defer them (found via Pydantic AI's local `search_tools`, since OpenRouter has no native tool search); paid and sponsored runs load every tool, because revealing tools changes the tool list at the start of the prompt and breaks OpenRouter's prompt cache. Each run's toolsets are wrapped in `arguments.Lenient`, which repairs quoted arguments (GLM sends arrays as JSON text and unset optionals as "") against the tool's schema before validation; the agent allows two retries per tool.
- Tools never take `chat_id`/`user_id` arguments: scope comes from `RunDeps`, and chat data is always filtered by the run's chat.
- `CAPABILITIES` are run-wide: web, Code Mode, Harness `ToolOutputLimits` (clamps run_code and history tool results when produced) and `RepairToolArguments` (fixes malformed tool-call JSON). Prefer a core or Harness capability over hand-rolled plumbing; ours stay where money, Telegram delivery or OpenRouter specifics need them (image generation, spend holds, approvals, context window).
- `web.py`: OpenRouter's `web_search` and `web_fetch` server tools as dynamic native tools (paid/sponsored only: search fees are in the response cost; fetch uses OpenRouter's own engine, never Derp's host). Searches run inside a model request, past the per-tool-call money check, so each request's `max_uses` is what the remaining hold covers at `web_search_price_usd` after one more turn like the latest; none → search is left out of that request. `inference.openrouter.DerpOpenRouterModel` maps `WebFetchTool`, which Pydantic AI doesn't for OpenRouter. `code.py`: Harness Code Mode as a pure sandbox — `run_code` runs Monty Python in a local worker with no Derp tools inside, no files, env, clock or network, capped time and memory; every tier, detached runs too.
- `history.py`: `search_history`, `read_messages`, `chat_query`, `digest` (+ deferred `chat_info`, `inspect_media`); current topic unless `whole_chat`. `memory.py`: notes and admin chat rules (paid/sponsored).
- `telegram.py`: output tools `send_poll` (quiz too), `send_dice`, `send_sticker` (chat favourites by emoji, then the global sticker index), `react`, all sequential and counted against `visible_outputs`; deferred ops edit/delete Derp's own messages and pin (admins). A final answer of just "." sends nothing when a tool output or reaction already answered.
- `games.py` (deferred): `post_polls` posts a series of up to 5 non-anonymous polls in one output slot — quizzes (scored, see `history/polls.py`) and/or regular polls; `most_likely_poll` offers the chat's most active members as options; `title_of_the_day` (groups) draws a "<title> of the day" among recently active members and keeps it for the chat-local day (`history/titles.py`; all-time counts in its result and the `title_leaderboard` chat query).
- `effects.py` (deferred, paid and sponsored runs): `make_meme` (picture, GIF, sticker or video; demotivator / lobster / panel), `reverse_media` (clips and voice backwards, pictures mirrored), `make_sticker` (a picture, cutout or clip frame as a static WebP sticker, no sticker packs), `identify_anime`, plus `identify_song` (ACRCloud keys set), `remove_background` (weights present) and `profile_photo` (every tier). Heavy effects (video encodes, cutouts) cost `effect_credits` on paid runs and are limited to `sponsored_effects_per_day` on sponsored ones; each becomes a `run_fees` row (0 credits on sponsored runs, which is what the daily count reads) only after Telegram accepted the result.
- `sources.py`: an effect's source is a named stored message of this chat (Derp's own outputs included, so tools chain by the `#id` they answer with), else the trigger or the message it replies to, a member's profile photo (by `person` — a name or @username resolved among this chat's members, ambiguity refused with the candidates — or by message sender, never a user id) or the chat photo.
- `utilities.py`: deferred toolbox over `derp/tools` (time zones, weather, rates, Wikipedia, Urban Dictionary, arXiv), plus WolframAlpha and the remote `run_program` only when their keys are set. `images.py`: `generate_image` (draw, or edit the current/replied/given message's image, a member's profile photo or the chat photo — Derp sends the result; bots can't set people's photos), paid funding only; the call itself lives in `../images.py`.
- `scheduler.py`: `schedule` (+ deferred `list_jobs`, `cancel_job`, `resume_job`) over `derp/scheduler`; `RunDeps.tz` is the chat's zone (UTC while unset, which the situation block says, and `schedule` then refuses clock times until the zone is set); setting it mid-run updates `deps.tz`; detached answers use the asker's private-chat zone. `self_service.py` (deferred, every tier): `wallet_status` (the /credits card; by DM in groups, the model never sees amounts there), `purchase_button` (an exact Stars invoice, or the pack menu; in groups a personal invoice or menu goes by DM, the chat's invoice is posted in the group and the chat's menu uses invoice links), `change_setting` (the /settings rules: admins for chat settings, but a chat with no time zone lets anyone set one; context off and a shorter retention only post the confirm button; free models on only posts the notice whose press consents; `name_me_when_i_chip_in` is the asker's patron anonymity), and `wallet_status` also passes the chat's recent patrons as an aside to mention only when asked, `leave_feedback` (`ops.feedback`).
- `about.py` + `../guide.md`: `about_derp(topics)` (every tier, always loaded) answers questions about Derp itself — the hand-written concept guide (no digits, a test enforces it) plus facts generated at call time from settings, the command menus, `FAMILIES` with tiers and the en privacy/terms pages, so values can't go stale. Deferred `search_source` / `read_source` (paid, sponsored) read the shipped `derp/` package only (lookups by key, never by path) and link excerpts to `settings.source_url` at `source_revision` (set at image build).
- Delivered outputs are recorded in `run_outputs` (`../models.py`); a send Telegram didn't confirm (`telegram.policy.AMBIGUOUS`) is reported with `telegram.unconfirmed` — it may have arrived, never resend — and neither recorded nor charged; actions priced above the approval line go through `../approvals.py`.

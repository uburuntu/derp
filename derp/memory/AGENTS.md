# Memory

- `models.py`: `notes` — chat notes (`user_id` null) and each member's own notes in one chat (`user_id` set). Nothing crosses chats. `chats.rules` (in history models) holds admin-written rules.
- `notes.py`: limits (500-char notes, room for a list kept as one note; 50 chat / 20 personal per chat, 2000-char rules), `load_memory`, `add_note` / `rewrite` (an edit in place, or the note's one pending edit: a `proposed` row whose `replaces_id` names the note, gone with it and discarded by a rewrite in place) / `decide` (an admin's approval or rejection), `matching` (note search), `notes_block` (the situation's notes part: the chat's `notes_mode` policy line on runs that have the memory tools, then the notes framed as untrusted data as "note 42", never `#`, newest first within `PROMPT_CHARS`, of which the asker's own notes get `MY_SHARE` first and either kind's unused share goes to the other (`budgeted`); a header counts the notes left out, which `find_notes` reaches) and `is_admin` (live `getChatMember`; private chats: the user is the admin).
- Permission model (`notes.py` `may_change`, the one rule: direct, propose or refused for adding, editing, forgetting or deciding; `remember`, `edit_note`, `forget_note` and the `/memory` buttons only word its verdict): chat notes follow `chats.notes_mode` — `auto` (Derp may save on its own, sparingly) / `members` (only when someone asks) / `admins` (only when asked; non-admin new notes and edits become `proposed`, approved via `/memory` buttons) / `off` (no new chat notes; only admins edit or forget the rest). The situation block states the mode's policy line (`notes.py` `NOTES_POLICY`, via `notes_block`) on runs that have the memory tools; the tools enforce what they can, "only when asked" is the model's to follow. Personal notes are always on; only their owner edits or removes them. Rules are admin-only and the only chat text in the trusted part of the prompt, so the model never words them unconfirmed: `set_chat_rules` applies text quoted verbatim from the admin's current message at once; anything reworded (or clearing) becomes `chats.rules_draft` shown with Apply/Cancel buttons that only the requesting admin can press (the callback carries a digest of the draft it was shown for).
- `command.py`: `/memory` lists rules, chat notes (named "note 12" like the model sees them; a pending edit by its note's number), the caller's notes (only in private or an ephemeral reply; a public group reply leaves them out) and pending proposals (approve/reject buttons, checked with `may_change` on press; a decided or vanished proposal loses its row, the others keep theirs); rules confirmation prompt and callback.
- Agent tools live in `derp/agent/tools/memory.py` (`remember`, `find_notes`, `edit_note`, `forget_note`, `set_chat_rules`; paid and sponsored runs only). Lists are one note that gets edited, taught in the tool descriptions; a list outgrowing its note is told to drop struck items or start a second list note.

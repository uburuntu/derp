# Keys — contributed API keys

- Owns `contributed_keys` (a person's OpenAI/Anthropic key: provider, picked model, monthly cap from `cycle_anchor`, the sealed OpenRouter sub-key and OpenRouter's credential id, pause/dead/removed state), `key_chats` (where it serves: offered → on → paused/off, enable order, notice marks), `key_requests` (a private plug-in step: paste → cap → model) and `key_models` (the scout's liveness/price of `settings.keys.models`).
- Derp never stores a provider key. `register.plug_in` makes a sub-key (its own spending on Derp's credits capped at `sub_key_limit_usd`/month, BYOK excluded), registers the key at OpenRouter for the provider's curated models plus its image model with `allowed_api_key_hashes` = the sub-key and `is_required` (no shared capacity), and pings the cheapest model; whatever fails before the key is saved is taken out again. The sub-key is AES-GCM sealed under `KEYS_SECRET` (`vault.py`). `pasted.py` spots a pasted key: `history.middleware` never stores or triggers on such a message, `flows` deletes it (edits too), and `history.capture` redacts any that slips into a stored text or quote.
- `routing.choose` is the first rung of `money.funding`: keys on in the chat (the owner's private chat has theirs on from the start), in enable order, skipping paused/dead keys and keys whose cap left (less a typical turn per run of theirs in flight) can't cover a typical turn (paused `cap` until the next cycle). Spend = `provider_calls.upstream_usd` since the cycle start. A pick the catalog no longer offers serves as the provider's recommended model (`serving_model`). `KeyRoute` carries the pin (`key_pin`: one model, `only` its provider, never ZDR), prices and the unsealed sub-key.
- A key run's failures (`failures.classify`): only errors the provider returned (OpenRouter's `metadata` names it) blame the key — 401/403 dead, 402/credit 429 exhausted, explicit refusal (or OpenRouter moderation) refused; anything else is plain `failed`. The runtime answers again without keys only if nothing was delivered and no tool ran. `notices`: chats hear once per pause/death (on their next ask, `announce`), owners once by DM; refusals are shown in the chat at most every `refusal_notice_hours` with Pause/Unplug here.
- `flows`: plug-in links `start=key-<signed chat ref>`, the paste/cap/model steps, the group card (admins turn on; owner-admins at once; a reused key's chat comes signed), Continue for waiting asks on enable (`money.free.offer_continues`), the owner's key page and the group's /settings keys page (`settings.panel` renders it). Every press re-checks owner/admin: chat buttons need a row offered to that group, only admins turn on, and a pause by the owner is theirs to lift.
- `sweep`: owners told when leaving a chat unplugged their key (`detach_member`, from `history.members`); dead keys removed after `dead_days`. `catalog`: daily liveness/price of curated models on their provider's own endpoint, a weekly smoke check, and every live key re-registered for today's list (`sync_registrations`, also at startup before polling: a model a deploy added would otherwise run on shared capacity, on Derp's credits).
- Telemetry stays content-free: status codes only, never keys, labels or error bodies.

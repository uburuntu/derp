# Inference

- `roles.py` defines hidden model roles and launch pins; users never choose models. `RolePin.rotated()` (first fallback leads, primary last) is the run's one retry after an empty reply or a refused request. OpenRouter's `models` fallback also covers rate-limited free models (verified live), so the free chain spans providers and ends with `openrouter/free` (any free model supporting the request's tools). Only `chat_free` is non-ZDR; every other role sends `provider.zdr=true` per request (an account-level ZDR toggle would also block the free models).
- `openrouter.py` is the provider seam: pin → `DerpOpenRouterModel` (Pydantic AI's `OpenRouterModel` plus the `openrouter:web_fetch` server tool, `openrouter` engine) + per-request settings (fallbacks via `openrouter_models`, ZDR, usage accounting, prompt caching, reasoning effort; `RolePin.fast` adds OpenRouter's soft `preferred_min_throughput`/`preferred_max_latency`, which prefer fast providers but never block a request — paid chat uses it). `conversation_id` (HMAC under a per-process key, no Telegram ids) goes out as `session_id` so OpenRouter keeps a chat topic (or an inline asker) on one provider, whose prompt cache is warm. Reasoning `"none"` is sent as `{"enabled": false}` because some providers ignore effort `none`.
- Cost is always OpenRouter's reported `usage.cost` (`provider_details["cost"]`, includes web-search fees). Never use `ModelResponse.cost()` (static price table). A paid chat response without one (cancelled streams, or a completed response missing it) is looked up with `OpenRouterAPI.generation` or estimated from the pin's price snapshot before it is ledgered (`agent.runs.price_unreported`), never recorded as free.
- `api.py` covers what Pydantic AI does not: Images API (no zdr flag → ZDR hosts pinned with `provider.only` per model), speech-to-text, catalog/endpoints for the model scout, generation lookups. An image or STT response without `usage.cost` is priced from settings (`image_price_usd`, `stt_price_usd_per_minute` × length), never recorded as free.
- A second provider would add a sibling module behind the same role → model/settings/usage functions; nothing outside this package imports OpenRouter types.
- `tests/live` holds opt-in smoke tests against the real API (`pytest -m live`, fractions of a cent).
- `models.py`/`ledger.py`: `provider_calls` is the single ledger of every paid provider call (chat turns, STT, images, digests, scout probes) with who funded it; metering, `/stats` and reconciliation read from it.
- `pins.py`: live pins live in `model_pins`, seeded from settings on startup: rows with `source='seed'` follow the code defaults (the old pin kept as `previous`, a new model's price snapshot dropped until the scout re-prices it), while `owner` and `scout` rows are never overwritten; `PinStore.get(role)` caches for 5 minutes and is the routing view: chat and sponsored chat pins without their own `max_price` get OpenRouter's `provider.max_price` (USD per 1M tokens) at `MAX_PRICE_HEADROOM` × the price snapshot, none without a snapshot; the ceiling applies to the whole request, so a fallback priced above it is skipped. `PinStore.all()` returns the stored pins without it (the scout writes pins back). Every pin change keeps the previous pin for one-step rollback; one that changes the model (apply or rollback) drops the price snapshot until the scout re-prices it.
- `scout.py` runs daily: auto-applies only safe changes (dead primary → first live fallback, price snapshot of the cheapest live ZDR route); challengers (turn prices count each route's cache-read price at the measured share of chat input served from the prompt cache over the last week) must pass a tiny live smoke check (Russian answer, tool call) and become `scout_proposals` for the owner to apply or ignore. Challengers come only from `settings.model_family_allowlist`, which leaves out OpenAI and Anthropic chat models by owner choice (too buttoned-up for Derp's voice).
- A change of default pin reaches production with the next deploy, for every role nobody chose by hand; rolling back from /stats marks the row `owner`, which pins it.

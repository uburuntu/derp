# Telegram plumbing

- `policy.py` is the request policy on every Bot API call: bounded flood-control retries for all methods; network/server retries only for reads. Never replay an ambiguous send — it may already be delivered (and charged).
- `sender.py` sends Markdown as Rich Messages with a plain-text fallback; every rich message is built with `rich()`, which makes line breaks hard (`text.hard_breaks`: Rich Markdown is GFM, where a single newline renders as a space), except in code blocks and `$$` formulas (a BadRequest means nothing was delivered, so the fallback is safe; it always passes `LinkPreviewOptions(is_disabled=True)`, because aiogram drops an explicit `None` instead of applying the bot default). Model-written Markdown is sent with `trusted=False`, which strips interactive tags (`tg-button`, `tg-thinking`) so injected text cannot fake Derp's controls, and remote media blocks / link previews that Telegram would fetch (exfiltration). Rich sends return blocks only, so the sent Markdown is kept as the returned message's `text`. A failure after some parts were accepted raises `PartialDeliveryError` carrying them, so callers record what really went out. `send_privately` DMs a person and returns False when they never started Derp.
- `Target` carries chat, forum topic (only when the trigger is a topic message) and the reply target; replies always set `allow_sending_without_reply` because the target may be deleted. A reply to an ephemeral command (message id 0) is ephemeral: `ephemeral_message_parameters` for the sender plus a reply to their `ephemeral_message_id` — accepted only within 15 s and not guaranteed to arrive, so never for invoices, approvals or reminders.
- `heartbeat.py` is the liveness contract: each successful `getUpdates` writes a timestamp; `python -m derp.telegram.heartbeat` is the healthcheck.
- `updates.py` lists the update types Derp subscribes to; handlers for a new type need it listed there. Reaction and `chat_member` updates only arrive when Derp is an admin.
- Verify Bot API semantics in `references/telegram-docs/bots-api.md` and aiogram behavior in `references/aiogram` before changing defaults.
- `media.py` `MediaGateway`: on-demand downloads by `file_id`, which only the receiving bot can use: every fetch names the owning `bot_id` and another bot's file is unavailable without asking Telegram (`file_unique_id` is the same for all bots but never downloadable). (Bot API 20 MB cap, timeout, magic-byte image sniffing, ~10 min in-process cache keyed by `file_unique_id`). File URLs contain the bot token — never log or return them; `MediaUnavailableError.reason` is the only safe detail. `profile_photo_bytes` / `chat_photo_bytes` fetch a person's latest profile photo or the chat photo through the gateway.

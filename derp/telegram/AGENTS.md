# Telegram plumbing

- `policy.py` is the request policy on every Bot API call: bounded flood-control retries for all methods; network/server retries only for reads. Never replay an ambiguous send — it may already be delivered (and charged).
- `sender.py` sends Markdown as Rich Messages with a plain-text fallback; every rich message is built with `rich()`, which keeps Markdown as written (`text.as_written`: Rich Markdown is GFM, where a single newline renders as a space, so line breaks are made hard; and Telegram reads a `#` starting a block as a heading even without a space, so `#3` is escaped), except in code blocks and `$$` formulas; untrusted names and titles inside trusted copy go through `text.literal` (a BadRequest means nothing was delivered, so the fallback is safe; it always passes `LinkPreviewOptions(is_disabled=True)`, because aiogram drops an explicit `None` instead of applying the bot default). Model-written Markdown is sent with `trusted=False`, which strips interactive tags (`tg-button`, `tg-thinking`) so injected text cannot fake Derp's controls, and remote media blocks / link previews that Telegram would fetch (exfiltration). Rich sends return blocks only, so the sent Markdown is kept as the returned message's `text`; `links` (a caller's rewrite of message references, `history.links`) applies only to what Telegram renders, so that `text` and Derp's history keep the answer as written. A failure after some parts were accepted raises `PartialDeliveryError` carrying them, so callers record what really went out. `send_privately` DMs a person and returns False when they never started Derp. `silent=True` sends without a notification sound (`disable_notification`).
- `Target` carries chat, forum topic (only when the trigger is a topic message) and the reply target; replies always set `allow_sending_without_reply` because the target may be deleted. A reply to an ephemeral command (message id 0) is ephemeral: `ephemeral_message_parameters` for the sender plus a reply to their `ephemeral_message_id` — accepted only within 15 s and not guaranteed to arrive, so never for invoices, approvals or reminders. `Target.answering_press` is the same for a button press (the press's `callback_query_id`, no reply); a BadRequest means it wasn't shown, so callers fall back to a visible or private message.
- `buttons.py` is the inline-button contract: `button`/`link`/`markup` build keyboards, `on_press` handlers get a `Press` (rich, ephemeral-aware `edit` and `strip(keep=...)`; every press answered exactly once; stale presses alerted). Refusals and errors are alerts (`deny`), successes a toast or silence; `answer` takes ready text for the English-only owner console. State lives in callback data and DB rows, never in memory, so buttons survive deploys; permission checks stay in each handler and run on every press (double taps included).
- `text.py` also holds `plain_emoji`, the one spelling of an emoji (no U+FE0F selector, no skin tone, as Telegram's reaction list writes them) that reactions and the sticker index compare. `bot.py` builds the bot and names it (`bot_username`, falling back to `FALLBACK_USERNAME`) for copy and deep links.
- `heartbeat.py` is the liveness contract: each successful `getUpdates` writes a timestamp; `python -m derp.telegram.heartbeat` is the healthcheck.
- `updates.py` lists the update types Derp subscribes to; handlers for a new type need it listed there. Reaction and `chat_member` updates only arrive when Derp is an admin.
- Verify Bot API semantics in `references/telegram-docs/bots-api.md` and aiogram behavior in `references/aiogram` before changing defaults.
- `media.py` `MediaGateway`: on-demand downloads by `file_id`, which only the receiving bot can use: every fetch names the owning `bot_id` and another bot's file is unavailable without asking Telegram (`file_unique_id` is the same for all bots but never downloadable). (Bot API 20 MB cap, timeout, magic-byte image sniffing, ~10 min in-process cache keyed by `file_unique_id`). Every picture a model gets (vision attachments, image-generation references, the profile-photo tool) goes through `normalize`, via `MediaGateway.image` (fetch + normalize; a known non-image MIME type is refused before downloading; `application/octet-stream` or none is unknown, so the bytes are sniffed) or `MediaGateway.normalize` (bytes): one Pillow decode of whitelisted formats (HEIC/HEIF via `pillow-heif`, registered once at import), capped in pixels and side, EXIF-upright, deep grayscale (16-bit, 32-bit, float) scaled to 8 bits, scaled to `VISION_SIDE`, transparency on white, JPEG — in a worker thread. An animated sticker (TGS) is never downloaded: `fetch` refuses a file Telegram stores as `.tgs`, since rows captured before sticker MIME types don't say. File URLs contain the bot token — never log or return them; `MediaUnavailableError.reason` is the only safe detail. `profile_photo_bytes` / `chat_photo_bytes` fetch a person's latest profile photo (largest, or the smallest of at least `side` px) or the chat photo through the gateway.
